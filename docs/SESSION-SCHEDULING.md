# Claude 会话调度

同一客户端的独立会话分别占用席位。明确的父子任务共用根会话席位；请求未提供会话标识时，才回退到设备等识别方式。租户范围、模型、账号授权、代理和额度限制仍参与候选筛选。

## 新会话如何分配

先找有请求容量、席位和额度预算的 VM；已有排队请求优先。调度等级相同时：

- **填充**：优先已占席位比例较高的 VM，然后比较请求负载；再优先额度余量较小的 VM，集中使用已有容量。满载或受限的 VM 不会仅因用量高而接收新会话。
- **平衡**：优先 `(正在运行 + 等待请求) / 当前有效并发` 较低的 VM，然后比较席位占用比例；再优先额度余量较大的 VM。
- 完全相同的候选按最近使用时间和 VM ID 排序，不随机。额度未知不假装成零用量或已接近耗尽。临界额度保护下有效并发为 1。

这里的“额度余量”同时考虑五小时和七天限制；“请求负载”反映当前拥堵。两者不是同一个值。

## 旧会话如何迁移

`pool.seat_migration_wait_ms` 默认 **10000**。已有会话在原 VM 等待达到此时间后，只有其他合格 VM 有空闲容量时才考虑迁移。

1. 同一会话或父子任务组正在执行的请求继续完成。
2. 准备迁移时，暂不把该组新请求送往旧 VM，等待该组排空；其他会话可以继续执行。
3. 同步取得目标容量，再移动该组席位和排队请求，更新相关绑定。已执行请求不重发。
4. 目标使用自己的账号和原生会话；旧 VM 的原生会话标识不带过去。迁移后的上下文可能需要重新写入缓存。
5. 目标须符合当前等待成员的候选范围；无法用请求中的会话消息重建的调用不启用此自动迁移。取消或超时会解除迁移等待状态。

已经排队的一批请求不会因为这次迁移立即反复搬家。明确指定 VM 的诊断调用保留固定目标。

## 等待期限

`pool.queue_wait_timeout_ms` 默认 **30000**。一次调用的调度等待累计最多 30 秒，原 VM 等待、全局排队及故障重选共用预算。迁移不重置预算；模型获得执行资格后的生成时间不计入这个调度等待预算。原生内核的单次槽位等待也受剩余时间参数限制。

此累计预算由调度器计时。原生内核槽位的实际等待时间不会回扣到共享预算，因此不能把它理解为整个调用链所有等待严格合计不超过 30 秒。

10 秒是开始评估迁移的时间，不保证第 10 秒一定搬走。如果该组尚未排空、目标不能接收或账号受限，就不能强行迁移。30 秒预算用尽后返回明确的容量错误及重试提示。

设置入口：调度设置 → 排队等待。默认分别为“会话迁移前等待 10 秒”和“等待总上限 30 秒”。每 VM 的并发、席位和额度保护配置独立生效；同一任务组仍使用一台 VM 的并发容量。

# IP 池对接：安装、使用与升级

本功能把 IP 池接入账号详情的「代理」页。管理员可以分配出口、复制登录链接、锁定登录期间的 IP、按首次位置就近更换，以及核对和释放出口。确认账号封禁后，可以标黑事件发生时的 IP，并跟进上游删除结果。

这是 `ip-pool-integration` 分支的扩展。本文说明配置和验收方法；阿里云 64G 的实际部署结果见 [部署与验收记录](ip-pool-deployment-20261022.md)。

## 适用范围

- Linux 宿主机，vm2api 控制面通过 Docker Compose 运行，能访问宿主机 Docker。
- 本机 Docker Claude 槽位。远程节点、KVM 和 Codex 槽位暂不支持。
- 当前连接格式为 VLESS、TCP、`security=none`、`encryption=none`。其他传输格式会明确失败。
- 槽位必须运行，才能从槽内核验实际公网出口。停止的槽位不能凭分配记录就算应用成功。
- IP 池支持独占分配、固定首次位置、版本检查、冷却结算、回收时凭据轮换、事件查询和可核对的删除状态。

维护操作只增加、解除本次 IP 操作的暂停标记。账号原有的额度、鉴权或人工暂停仍然保留。

## 服务器配置

控制面需要包含本分支的 IP 池功能。官方 `latest` 镜像不包含本功能，不能仅拉取官方镜像完成此扩展的升级。

将 IP 池 Key 放在服务器私有文件中，例如宿主项目目录下的 `data/private/ip-pool.key`，目录权限 `0700`、文件权限 `0600`。文件内只放有效的 Key，不能提交到 Git、写入前端或粘贴进日志。标准 Compose 已把项目的 `data` 挂载到容器内 `/opt/vm2api/data`。

在现有私有 `.env` 中增加：

```dotenv
KIN_IP_POOL_URL=https://ip-pool.example.com:8443
KIN_IP_POOL_KEY_FILE=/opt/vm2api/data/private/ip-pool.key
KIN_IP_POOL_INSTANCE=aliyun64g
```

| 配置                   | 含义                                                               |
| ---------------------- | ------------------------------------------------------------------ |
| `KIN_IP_POOL_URL`      | IP 池的 HTTPS 地址，可带 `/api/v1`，不能带凭据、查询参数或片段。   |
| `KIN_IP_POOL_KEY_FILE` | 控制面容器内可以读取的私有 Key 文件路径，不是 Key 内容。           |
| `KIN_IP_POOL_INSTANCE` | 这套部署固定且唯一的标识。分配关联依赖它，建立分配后不要随意改名。 |

把用户已经安装、验证可用的 Xray 二进制复制到项目 `bin/xray`，保留可执行权限，并核对架构与宿主机一致。本功能复用该版本，不会替用户下载或升级 Xray。标准 Compose 已挂载 `bin`。

构建前备份当前镜像版本，以及私有 `.env`、`vms`、`data` 和 `bin`。`data/ip-pool/runtime` 含连接凭据，备份也应只保存在私有位置。

### 新部署或完整源码构建

在本分支项目根目录运行：

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml build vm2api
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d vm2api
```

已有定制镜像名称或 Compose 覆盖文件的部署，应保留原有配置并使用相同的文件组合。

### 现有阿里云 64G 部署

现服务器安装目录为 `/opt/vm2api`，实际 Compose 文件是 `/opt/vm2api/compose.yml`，基镜像为 `v1.3.201`。这次在现有版本上应用 IP 池功能，未直接用本地分支的完整源码替换生产版本。

服务器原有源码比本地分支旧。`src/lib/admin/panel-routes.mjs`、`src/lib/pool/pool-scheduler.mjs` 和 `src/lib/pool/schedule-eligibility.mjs` 必须按 IP 池功能差异逐项合入，保留服务器已有的限流补丁，不能整文件覆盖。独立 IP 池模块和构建后的前端按部署需要加入；具体镜像和验证结果见部署报告。

维护这套部署时使用实际的 `compose.yml`，保留原环境变量、挂载、端口和服务器补丁，并保存可回退的旧镜像。例如查看状态：

```bash
docker compose -f /opt/vm2api/compose.yml ps
```

控制面启动后，以管理员身份打开一个本机 Docker Claude 账号的「代理」页，确认出现「IP 池」卡片。未配置时不影响原有代理功能；配置不可用时卡片显示错误。

## 日常使用

管理员可以直接在虚拟机卡片找到公网出口摘要和 **IP 管理** 入口：机架大、中、小卡均显示，列表视图位于账号列，弹出的详情卡位于「槽位 → IP 池」。点击 **IP 管理** 会直达对应虚拟机的「代理」页，顶部就是「IP 池」卡片；刷新页面仍保持在该页签。该入口仅管理员可见。

摘要读取 IP 池已有分配与槽内核验记录，不使用代理服务器地址代替公网出口，也不会在显示卡片时主动探测。显示「出口」表示当前分配的 IP、版本与已有核验记录一致，可悬停查看核验时间；显示「分配出口」表示当前分配尚未核验为实际出口。已释放或已标黑的 IP 不再作为当前出口显示，旧核验记录仅在提示中标为历史；没有可确认的数据时显示「未知」。需要重新确认实时出口时，再进入 IP 管理点击「核对出口」。

1. **分配并应用**：分配一个独占出口，接入本机并核验槽内实际出口。页面分别显示「IP 池已分配」和「本机已应用」，只有核对一致后才恢复本次暂停。
2. **指定公网 IP**：从当前可用列表选择，支持按 IP 或地区搜索及刷新，也可手动输入实际公网出口 IP；不能填写代理入口地址、链接或端口。列表仅预览，不会预留出口。没有分配时按目标初始分配；已有分配时换绑到目标出口。确认时再次检查既有独占、健康、冷却、标黑和分配策略，不能分配时明确失败，不回退到其他 IP。指定当前已分配的同一个 IP 时只核验现有出口，不发起换绑、不改变分配版本，也不重建本机连接。
3. **复制 VLESS 链接**：复制时自动暂停账号、等待当前请求结束并锁定出口。链接只在复制时获取，不存入前端缓存。让登录浏览器使用该链接，核对浏览器公网出口后登录。
4. **已完成登录，解锁**：登录完成并关闭登录页面后点击。系统再次核对出口，再解除本次登录暂停。也可以先点「开始登录，锁定 IP」，再复制链接。
5. **就近更换**：先结束登录并关闭使用旧出口的浏览器连接。系统始终参考首次分配的位置寻找附近可用 IP，不会把上一次替换位置当成新锚点。
6. **核对出口**：从当前运行的槽位检测实际公网 IP。检测失败或与分配不一致时保持暂停。
7. **释放出口**：结束使用旧出口的浏览器连接后确认释放。账号解绑，旧连接清理并确认结束后才结算冷却。重新使用账号前需要再分配出口。

指定公网 IP 需要上游 `GET /api/v1/capabilities` 声明 `features.exact_exit_ip = true`，初始分配和换绑接口接受 `target_exit_ip`。不支持时会在暂停和分配前明确提示，不改用普通分配。接口要求和上游补丁见 [指定公网出口 IP](ip-pool-exact-exit.md)。

登录锁期间可以复制、核对和结束登录，不能换 IP、释放或重新分配。账号已交给 IP 池管理后，原有手动绑定、解绑与分配入口不再用于该账号。

IP 池冻结旧出口、本机排空请求和关闭浏览器连接分别解决不同问题，都需要完成。冷却结束或提前结算后，上游轮换旧凭据，让旧链接失效。

### 出口与时区同步

「分配并应用」「就近更换」和「核对后应用」都会使用当前分配的公网 `expected_exit_ip` 显式查询 Geo 元数据，并要求返回的 IP 与该公网 IP 一致，再取得有效的 IANA 时区。不能用代理入口 IP 推断出口位置，也不能把旧 Geo 缓存当成这次查询成功；时区未知时保持未知并暂停，不猜测为 UTC。

应用时将同一时区写入 VM 配置、`fingerprint`、Docker 的 `TZ` 和内核配置。运行中的槽位如果时区发生变化，会重建容器，让新的 `TZ` 实际生效；时区未变则 reload。常规重建保留账号 home，不清空登录和账号数据。另行要求清空测试槽位数据属于独立的一次性操作，不属于换 IP 或时区同步的默认行为。

停止的槽位不会因此自动开机。Geo 查询、运行时配置核验或槽内实际公网出口核验任一失败，都会保留本次维护暂停；只有全部核验通过后才解除本次暂停，账号原有的其他暂停仍保留。

## 失败与恢复

页面显示「等待完成」或「需要处理」时，先看错误信息，再点 **核对后应用**。这会查询已有分配并继续完成本机应用；不会因为响应丢失再次发起换 IP。

| 情况                                          | 处理                                                                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 分配或换 IP 请求超时，结果未知                | 先核对后应用。不要连续点击分配或更换；指定目标会保留，重启后也不会丢失或改分其他 IP。                                        |
| 核对后明确没有分配                            | 页面才重新提供分配入口。                                                                                                     |
| 上游未声明指定 IP 能力                        | 更新 IP 池后再试；本次不会暂停账号或改用普通分配。                                                                           |
| 指定目标不可分配                              | 核查目标的占用、冷却、健康与策略，处理后再明确发起操作；不会自动换成其他 IP。                                                |
| 上游分配与指定目标不一致                      | 保持暂停，核查上游并纠正目标分配后核对后应用；单点应用不能跳过目标校验。如需放弃本次目标，先明确释放并完成清理，再重新分配。 |
| 结果未知后分配列表格式错误                    | 保留未知操作、指定目标和暂停，待上游恢复后再核对；无效响应不能当作确认没有分配。                                             |
| 槽位停止                                      | 启动槽位后核对后应用；维护暂停保持到实际出口验证成功。                                                                       |
| 实际出口不同或连接失败                        | 保持暂停，检查节点和网络后核对后应用。普通连接故障不等于账号封禁。                                                           |
| Geo 查询失败、IP 不符或时区未知               | 保持暂停，检查当前分配与 Geo 服务后核对后应用；不能用旧缓存、代理入口位置或 UTC 代替。                                       |
| VM、fingerprint、Docker TZ 或内核时区核验失败 | 保持暂停，修复运行时配置后核对后应用；需要重建容器时保留账号 home。                                                          |
| 登录期间未完成操作                            | 检查浏览器状态，完成登录并关闭登录页面后解锁。                                                                               |
| 控制面在操作期间重启                          | 恢复后保留暂停，核对后应用完成上次操作。                                                                                     |
| 上游记录被其他操作改变                        | 保持暂停，核对并应用当前分配，不能直接按旧版本再次更换。                                                                     |

## 确认封禁与标黑

只有确认账号封禁后才使用「确认封号，标黑 IP」。对话框要求核对 **事件发生时的公网 IP 和发现时间**；换过 IP 时不能直接把当前出口当成事件出口。系统使用曾经实际核验过的历史记录核对该 IP。

确认后账号保持暂停，上游标黑并删除相关节点。若请求结果未知或删除失败，使用「核对并重试删除」继续追踪同一个事件。

只有 `deletion_state == "succeeded"` 才表示上游确认删除成功。`failed`、`pending`、`unverified` 都不能当作删完；删除失败的出口仍然被排除，不会重新分配。`endpoint_access_revoked` 单独说明旧凭据是否已经失效。

删除已标黑的账号槽前，还需在「代理」页顶部的「IP 池」卡片释放出口。上游确认删除及凭据失效、分配已释放、本机代理与旧连接全部清理且没有登录锁或处理中操作后，回到「运维」点击「删除此槽位」。系统会重新读取当前绑定，确认没有代理才放行；封禁及历史审计记录仍保留。IP 池卡片负责清理出口，不提供删除虚拟机的按钮。

额度用尽、认证失败、网络超时都不自动触发标黑。

## 升级与回退

`main` 跟随官方，自己的改动保留在 `ip-pool-integration`。同步前先保存工作区改动：

```bash
git fetch upstream
git switch main
git merge --ff-only upstream/main
git switch ip-pool-integration
git merge upstream/main
```

冲突处理重点是面板路由挂载、账号代理页、调度暂停检查和后台监测暂停检查。不要把新增的 IP 维护暂停检查当作多余代码删掉。

同步 Git 分支只更新源码，不会自动升级现有生产基镜像。现有阿里云部署继续按目标版本差量合入，并保留限流补丁；将来要完整升级生产基镜像时，应单独核对兼容性、测试和回退方案。

安装更新后的依赖，再运行相关测试和构建：

```bash
npm ci
pnpm -C web install --frozen-lockfile
node --test test/unit/ip-pool-*.test.mjs
pnpm -C web test src/features/ip-pool/model.test.ts src/lib/vm-status.test.ts
pnpm -C web build
```

调度或后台监测代码合并有变化时，再运行对应已有测试。通过后按所选部署方式构建镜像，在测试账号验收后再用于现有账号。

回退要同时考虑运行状态：仍有受 IP 池管理的账号时，不要直接切回不认识维护暂停标记的官方镜像。先保留旧集成镜像与私有状态；需要回官方时先在集成版本中完成释放和连接清理，并逐个确认账号状态。

## 实际验收方法

先用一个本机、正在运行的测试槽位，记录分配 ID、版本、首次位置、分配 IP 和槽内实际 IP，逐项验收：

- 分配后两处出口一致；原有账号暂停不被解除。
- 指定公网 IP 能完成初始分配和已有账号换绑；实际应用出口必须等于目标。上游未声明 `features.exact_exit_ip` 时，在暂停和分配前失败；目标不可用时不回退到其他 IP。
- 指定当前同一个 IP 时只核验，不新增分配或换绑、不改版本、不重建连接。登录锁期间同样不能指定 IP。
- Geo 显式查询的是分配的 `expected_exit_ip`，返回 IP 一致且 IANA 时区有效；VM、`fingerprint`、Docker `TZ` 和内核配置使用同一时区。
- 运行中更改时区后容器已重建，账号 home 保留；时区未变时走 reload。停止槽位执行应用不会自动开机。
- Geo 失败、返回 IP 不符、时区未知、运行时配置不符或槽内出口不符时均保持暂停；旧 Geo 缓存和代理入口 IP 不能让检查通过，也不回填猜测的 UTC。
- 复制链接后进入登录锁；更换、释放不能在锁定时执行；完成登录后能解锁。
- 更换后首次位置不变，实际出口与新分配一致，旧连接结束后上游完成冷却结算。
- 人为制造接口超时或本机应用失败后，保持暂停；核对后应用恢复同一分配，不多分配、不多换一次。
- 指定 IP 操作结果未知或上游返回错误目标后，重启仍保留目标约束，核对后应用不能恢复错误出口；无效分配列表不能清除未知操作或目标。
- 释放后本机解绑，旧连接清理结果可核对。
- 标黑和删除失败路径用专用测试记录验证，不把普通测试故障上报成真实账号封禁，也不删除其他账号正在使用的出口。

记录每一步的实际结果。网页显示正常、单元测试通过或健康接口返回成功，都不能替代槽内实际出口核验。

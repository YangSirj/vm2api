# 指定公网出口 IP

管理员在 **VM 卡片 → IP 管理 → 指定公网 IP** 输入目标公网 IP 并确认。没有分配时执行初始分配；已有分配时换绑到目标出口。这里填写实际出口 IP，不是代理服务器入口地址。

系统只接受符合当前条件的目标，**不可用就明确失败，不回退到其他 IP**。原有独占、标黑、冷却、健康、政策、首次位置及登录锁规则全部保留；指定 IP 不绕过这些检查。应用后仍须核验槽内实际出口与分配一致，才能解除本次维护暂停，账号其他暂停原因保留。

若指定的 IP 就是当前分配，vm2api 只核验当前出口，不调用上游换绑，不修改分配版本或触发旧出口回收。登录锁期间仍不能执行分配或换绑操作。

## 上游要求

IP 池的 `GET /api/v1/capabilities` 必须返回 `features.exact_exit_ip = true`。不支持时 vm2api 明确提示更新 IP 池，不改用普通分配。

上游 `POST /api/v1/assignments` 和 `POST /api/v1/assignments/{id}/replacements` 接受可选 `target_exit_ip`，用既有 `canon_ip` 校验公网地址，在原分配锁内从原合格候选中匹配。目标不可用返回 `CANDIDATE_INELIGIBLE`；同时提供 `proxy_id` 时，两者必须匹配。已有未释放分配与指定目标不同也会明确拒绝，不能直接返回另一个 IP。

最小补丁见 [deploy/ip-pool-exact-exit.patch](../deploy/ip-pool-exact-exit.patch)。它只增加能力声明及两个分配入口的目标筛选，不包含密钥或运行状态。不提供 `target_exit_ip` 时保持上游原行为。

当前基线含上游独立的 `exit_ip` / `proxy_id` / `force` 功能，补丁保留该功能。vm2api 的指定公网 IP 使用 `target_exit_ip` 路径，不调用上游 `forced()`；即使请求同时带 `force=true`，也不能借此跳过原候选筛选。

同时保留上游最新的重复分配逻辑：已有未释放分配且未指定节点时，先直接返回原分配；显式指定现用节点时，先按原逻辑校验，再返回原分配；指定不同节点仍按原上游逻辑换绑。无 `target_exit_ip` 分支沿用当前基线原文，仅增加缩进。
